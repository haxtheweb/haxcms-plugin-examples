# Log (core, optional)

One unified log for every plugin. Implements the core contract `log.sink`: core hands every `ctx.log` entry (plugin id, level, message) to each enabled sink. This plugin keeps them in a system store, rotates them on the `rotate` schedule, and serves `logList` for the log page.

Without this plugin, entries still go to the server log; the health chips on the plugin dashboard come from core, not from here.

- Store: `entries` (system scope)
- Schedule: `rotate` (daily) keeps the newest `maxEntries`
- Operation: `logList` (filter by plugin and level; filtering is the plugin's job)

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| operation | `logList` | `GET /system/api/v1/plugins/<id>/entries` (bearerAuth + userTokenHeader) | Returns the newest entries first, filtered by plugin and level, for the log page. |
| contract | `log.sink` write | core calls it (all) | Appends each entry core hands over to the stored history, capped at maxEntries; entries below the configured level are dropped. |
| schedule | `rotate` | `0 0 1 * *` | Keeps only the newest maxEntries each month; writes already cap the size, and this also drops a month's backlog. |
