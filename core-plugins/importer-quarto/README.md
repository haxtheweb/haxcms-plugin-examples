# Import from Quarto (core)

**Today:** `POST /system/api/v1/site/import/quarto` in [haxcms-nodejs](https://github.com/haxtheweb/haxcms-nodejs) (`src/systemRoutes/v1/routes/imports/convertQuartoToSite.js`, mirrored in [haxcms-php](https://github.com/haxtheweb/haxcms-php)) takes a GitHub repository URL, reads the file tree and `_quarto.yml` through GitHub's API, renders every page with markdown-it plus Quarto-specific rewrites, and returns items, files, the site license and license notices for `createSite`.

**As a plugin:** implements the core contract `import.platform` (dispatch `chosen`). Markdown is converted through the platform (`ctx.contracts.call("import.file", ...)`, answered by the `import-markdown` plugin), so this plugin carries no markdown parser.

- **Source:** a GitHub repository URL (`https://github.com/<owner>/<repo>`, optionally `/tree/<branch>`), read from `api.github.com` (repository and file tree) and `raw.githubusercontent.com` (files), the only hosts it may reach; or an uploaded zip of the repository (`files: [{ name: x.zip, data }]`, read with `ctx.archive.read`; a GitHub download's top folder is dropped), which fetches nothing.
- **Outline** from the shallowest `_quarto.yml`: `book.chapters` (parts included) then `book.appendices`; else `website.sidebar` contents (sections, `auto`, globs); else `website.navbar` left and right (menus become pages with children); else every page in the tree, index first. Ignored as Quarto ignores them: `_` and `.` paths, README/AGENTS/CLAUDE files, `node_modules`, `renv`, `venv`, `*_files`, `*_cache`, `project.output-dir`; `project.render` narrows the set. A group without a page becomes an empty landing page; external entries are skipped.
- **Pages:** the front matter `title`, else a leading `# heading`, names the page unless the outline gave it a label. Code chunks lose their braces and `#|` options (`echo: false` / `include: false` chunks are dropped); `{=html}` blocks pass through. Callouts become `stop-note` (title from `title=`, else the first heading inside, else the type). `content-visible` / `content-hidden` are applied for HTML output; other fenced divs keep their id and classes. Heading and image attribute blocks are removed (`fig-alt` becomes the alt text), bracketed spans keep their classes, cross-references keep their key without the `@`. The `video` shortcode becomes `video-player`; other shortcodes are removed.
- **Links and files:** links to other pages (`x.qmd` or `x.html`) point at the imported slugs; images become `media-image`; repository images and documents the pages use are listed in `files` (`files/<name>` with the raw URL) for core to fetch; other relative references point at the raw file. A page that cannot be read links to the published page when `site-url` is set. Scripts and inline handlers are dropped (core sanitizes again).
- **Input:** `{ url }` or `{ files: [{ name, data (base64) }] }`. **Output:** `{ title, items: [{ id, title, slug, parent, order, indent, content, metadata: { sourceType, quarto: { repo, branch, path }, source? } }], files }`, or `{ error }`.

**Not ported yet**

- License handling: core reads `license` (project file, page front matter, or the repository's LICENSE file), refuses all-rights-reserved work, appends a `license-element` to each page and returns license notices. `import.platform` has no place for site settings or notices yet.
- Jupyter notebooks (`.ipynb`), `{{< include >}}`, footnotes, tables and other markdown the shared converter does not know, `author` and `accessed` metadata, `truncated` / `unmappedComponents` reporting, and the fetch time budget (the 500-page cap is kept).
- `_quarto.yml` is read with a small YAML subset (block maps and lists, scalars, `[a, b]`, `|` and `>`); flow maps (`{ href: x }`), anchors and aliases are not read.
- From a zip upload, images and files are not listed (`files` takes URLs only), so their references stay as written.
