# Import from Pressbooks (core)

**Today:** `POST /system/api/v1/site/import/pressbooks` in [haxcms-nodejs](https://github.com/haxtheweb/haxcms-nodejs) (`src/systemRoutes/v1/routes/imports/convertPressbooksToSite.js`, mirrored in [haxcms-php](https://github.com/haxtheweb/haxcms-php)) takes a book URL, finds its REST API (`/wp-json/pressbooks/v2`), and returns front matter, parts with their chapters, and back matter as items for `createSite`. An uploaded `.html` file is split by the generic HTML splitter.

**As a plugin:** implements the core contract `import.platform` (dispatch `chosen`).

- **From a URL** (core's main path): any page of the book works; the base is found by trying the pasted path and each shorter one (stopping at `chapter`, `part`, `front-matter`, `back-matter`, `toc`, `wp-json`) until the REST index lists `pressbooks/v2` or the TOC answers. Each section's full record is read for its title and content. Sections with `export: false` are skipped; order follows `menu_order`. Chapters sit under their part (`parent`, `indent: 1`, slug `part/chapter`). Root-relative `href`/`src`/`poster`/`srcset` point at the book's host. A section that cannot be read comes back as `<p></p>`. It may fetch only the host of the URL it is given (`egress: { input: url }`).
- **From an XHTML export** (`files: [{ name: book.html, data }]`): splits the file at Pressbooks' `front-matter`, `part`, `chapter` and `back-matter` sections, using each section's title heading and its `ugc` content, with chapters under the part before them. Nothing is fetched.
- Scripts and inline event handlers are dropped; core sanitizes page HTML again on save.
- **Input:** `{ url }` or `{ files: [{ name, data (base64) }] }`.
- **Output:** `{ title, items: [{ id, title, slug, parent, order, indent, content, metadata: { sourceType, pressbooks, source? } }] }`, or `{ error }`.

**Not ported yet**

- The site license core reads from the book's metadata (`site.license`): `import.platform` has no place for site settings yet.
- Media files are not listed in `files`; images keep their (absolute) URLs on the source book, as core does today.
- EPUB and other export formats; only the single-file XHTML export is read.
- Core's slugs are not de-duplicated; here a repeated slug gets `-2`, `-3`.
