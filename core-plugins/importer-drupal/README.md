# Import from Drupal (core)

Copies a Drupal 8+ site into a new site through its JSON:API. Implements the core contract `import.platform` (`convert`), dispatched to the importer the person picks (`dispatch: chosen`).

## What core does today
`convertDrupalToSite` (haxcms-nodejs `systemRoutes/v1/routes/imports/convertDrupalToSite.js`, haxcms-php `convertDrupalToSite.php`, about 1,600 lines each) discovers `<base>/jsonapi`, reads node--page and node--book, file--file, every media bundle, menus and menu links, rewrites page HTML, and hands items plus a file map to `createSite`.

## What the plugin does
- Accepts any URL of the site; finds JSON:API at that path, then each parent path, then the origin. Only that host is reachable, and only during the call (`egress: { input: url }`); pagination links to other hosts are refused.
- Pages are node--page plus node--book records (first record wins per node id), read page by page through `links.next`.
- Files: published file--file records under `/sites/<site>/files/` (or `/files/`) with an extension core's bulk import accepts are listed in `files` as `files/<path below files/>`, at most 2,000. Links in page HTML to those files are rewritten to the `files/` path (src, href, poster, source, srcset).
- Media: `<drupal-media data-entity-uuid>` embeds and `field_media` references become `media-image`, `video-player` (also remote video), `audio-player` in `media-playlist`, or a link for documents; unresolved embeds are dropped. Root-relative links are made absolute to the site.
- Outline: menu_link_content records (the main menu, or the menu linking the most pages; pages linked only in other menus follow at the top level), else book fields (`book.pid` / `book.weight` and the flat variants), else every page by creation date. A top-level page with no content but with children is dropped and its children take its place. Pages no outline reaches go under a hidden `additional pages` group.
- Each item's metadata keeps `sourceType`, `source` (`<base>/node/<nid>`), `published` and `drupal: { nid, uuid, type, inOutline }`. Ids are `item-<nid>`. The title is core's site machine name from the URL. Scripts and inline handlers are removed (core sanitizes again).
- Returns `{ error }` when no JSON:API is found, or it exposes neither node--page nor node--book, or those have no readable records.

## Not ported
- The menu-items endpoints of the jsonapi_menu_items, jsonapi_frontend_menu and jsonapi_menu modules (and the menu--menu list and path alias matching they need); the outline comes from menu_link_content, book fields or creation order.
- The import statistics core returns beside the items (`drupal: { pagesTotal, filesSkipped, mediaResolved, ... }`); the contract has no slot for them.
- File references are rewritten with a regular expression on double- or single-quoted attributes instead of an HTML parser, so entity-encoded URLs are left as they are.
- `parentId` (import under an existing page) is not part of the contract input yet.
