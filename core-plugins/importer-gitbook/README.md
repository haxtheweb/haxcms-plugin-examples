# Import from GitBook (core)

Turns a GitBook (a `SUMMARY.md` table of contents plus Markdown pages) into a new site. Implements the core contract `import.platform` (`convert`), dispatched to the importer the person picks (`dispatch: chosen`). Depends on `import-markdown`: each page's Markdown is converted by calling `ctx.contracts.call("import.file", "convert", { name: "page.md", data })`, so this plugin has no Markdown parser of its own.

## What core does today
`convertGitbookToSite` (haxcms-nodejs `systemRoutes/v1/routes/imports/convertGitbookToSite.js`, haxcms-php `convertGitbookToSite.php`) takes a GitHub repository URL, asks api.github.com for the default branch and the full file tree, reads `SUMMARY.md` and each page from raw.githubusercontent.com, renders Markdown with markdown-it (Node) or Michelf Markdown (PHP), and stages every non-Markdown file in the repository as a download.

## What the plugin does
- Accepts a github.com repository URL (`https://github.com/<owner>/<repo>`, optionally `/blob|tree/<branch>/<folder>/SUMMARY.md`), or any URL of the book's folder or its `SUMMARY.md` (raw.githubusercontent.com, a docs host). Only that host is reachable, and only during the call (`egress: { input: url }`). For github.com it reads through github.com's own `/raw/<branch>/` paths, trying `main` then `master` when no branch is named.
- The `SUMMARY.md` list nesting becomes the page tree. An entry without a link adds a level, and its children attach to the entry above it, as core does. External links and links that climb above the book's folder are skipped.
- Slugs come from the page path (`chapter/README.md` becomes `chapter`, `chapter/intro.md` becomes `chapter/intro`), made unique with `-2`, `-3`.
- Images and other files the pages reference by relative or root path are rewritten to `files/<path>` and listed once each in `files` for core to fetch. Scripts and inline handlers are removed (core sanitizes again).
- Returns `{ error }` when no `SUMMARY.md` is found or it lists no pages.

## Not ported
- The GitHub API calls (default branch, recursive tree): api.github.com and raw.githubusercontent.com are other hosts than the one the person gives. So only files the pages reference are listed, not every file in the repository, and a github.com repository whose default branch is not `main` or `master` needs the branch in the URL. github.com's `/raw/` paths redirect to raw.githubusercontent.com; whether ctx.fetch may follow that redirect is a platform decision (see AGENTS.md).
- Core imports only the first list in `SUMMARY.md`; this plugin reads every list item, so books split into `## Part` sections come over whole. Part headings themselves do not become pages.
- `parentId` (import under an existing page) is not part of the contract input yet.
