# OAuth (core, optional)

Lets other apps act for a person with tokens that person approves, instead of their password. HAXcms becomes an OAuth 2.1 authorization server: authorization code with PKCE (S256 only), short access tokens, rotating refresh tokens, audience-bound tokens (RFC 8707), revocation (RFC 7009), and, if you turn it on, dynamic client registration (RFC 7591). Off until you enable it, and it needs the **Issuer URL** setting (this HAXcms's public address) before it does anything.

It is not tied to any one app. A plugin that accepts its tokens implements the `oauth.resource` contract this plugin defines: it names its audience URL and scopes (what the consent screen shows) and decides, call by call, what a token may do. MCP is the first (`core-plugins/mcp`), and it requires this plugin.

- **People approve, and can take it back.** The consent screen (`admin/oauth/authorize`) shows which app, which resource and which scopes. Every approval is listed for the person who gave it (`oauthGrantList`) and can be revoked (`oauthGrantRevoke`), which stops every token from it at once.
- **Headless clients** (stdio MCP, scripts) get a personal token for one resource and its scopes (`oauthPersonalTokenCreate`), shown once.
- **Nothing secret is stored**: tokens and codes are kept as SHA-256 hashes; clients are public (no client secrets).
- **Reused refresh tokens revoke the approval**: a refresh token works once; presenting it again is treated as a leak.
- **Grants reach the resource safely**: on each request carrying one of its tokens, this plugin checks the token, asks the resource, and passes the verified grant on in `x-hax-oauth-grant`; it removes any copy a client sends.

What core still has to provide is listed in `spec/GAPS.md` (1s): serving the metadata at `/.well-known/oauth-authorization-server`, accepting these tokens as the caller's identity on core routes, and a system-level public URL.

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `rest.before.request` | a request to a plugin or core route is about to reach its handler | Drops any x-hax-oauth-grant header a client sent; for a request carrying one of this plugin's tokens, refuses it unless the token is live and the resource it was issued for allows the call, then passes the grant on in that header. |
| operation | `oauthMetadata` | `GET /system/api/v1/plugins/<id>/metadata` (public) | Publishes the authorization server metadata (RFC 8414) MCP clients read first; core also serves it at /.well-known/oauth-authorization-server. |
| operation | `oauthAuthorizeCheck` | `GET /system/api/v1/plugins/<id>/authorize` (bearerAuth + userTokenHeader) | Validates an authorization request and describes it for the consent screen: which app, which resource, which scopes. |
| operation | `oauthAuthorizeDecide` | `POST /system/api/v1/plugins/<id>/authorize` (bearerAuth + userTokenHeader) | Records the person's answer: on approval it stores a grant and a single-use code bound to the PKCE challenge, then returns the redirect back to the app. |
| operation | `oauthToken` | `POST /system/api/v1/plugins/<id>/token` (public) | Exchanges a code and its PKCE verifier, or a refresh token, for an access token and a new refresh token; a refresh token used twice revokes its whole grant. |
| operation | `oauthRegister` | `POST /system/api/v1/plugins/<id>/register` (public) | Registers a public client (no secret) when dynamic registration is turned on; redirect URIs must be https, or http on this machine. |
| operation | `oauthRevoke` | `POST /system/api/v1/plugins/<id>/revoke` (public) | Revokes a token; a refresh or personal token takes its whole grant with it. |
| operation | `oauthGrantList` | `GET /system/api/v1/plugins/<id>/grants` (bearerAuth + userTokenHeader) | Lists the approvals the signed-in person has given and not revoked: which app, which resource, which scopes. |
| operation | `oauthGrantRevoke` | `DELETE /system/api/v1/plugins/<id>/grants/{id}` (bearerAuth + userTokenHeader) | Takes an app's access away: the grant and every token issued under it stop working at once. |
| operation | `oauthPersonalTokenCreate` | `POST /system/api/v1/plugins/<id>/personal-tokens` (bearerAuth + userTokenHeader) | Issues a token for a headless client (stdio MCP, a script) without the browser flow, for one resource and its scopes; the raw token is returned once. |
| operation | `oauthResourceList` | `GET /system/api/v1/plugins/<id>/resources` (bearerAuth + userTokenHeader) | Lists what tokens can be issued for (every configured oauth.resource implementer) and the scopes each accepts. |
