# pwa (offline support)

Offline support and the old-browser upgrade prompt, extracted from core.

**Today in core:** `site.json` keeps `metadata.site.settings.sw` and `forceUpgrade`; core renders `service-worker.js` and `offline.html` as managed files and adds the registration script when `sw` is on (`getServiceWorkerScript`, `getServiceWorkerStatus`); `forceUpgrade` sends old browsers to `assets/upgrade-browser.html`.

**As a plugin:** per-site settings (off by default); `rebuild.after` writes a network-first worker and the offline page as managed files; turning it off (or disabling the plugin) writes a worker that clears its caches and unregisters itself, so visitors who installed the old one are not stuck; core moves both settings out of `site.json` on first enable (`legacy.settings`).

**Core changes when extracted (not made here):** remove `sw`/`forceUpgrade` from the form and `saveManifest`, the service-worker template and registration code, and the `forceUpgrade` template variable.

Tests: `node harness/run-cases.mjs core-plugins/pwa`.

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `render.before.head` | the head is about to be assembled | When forceUpgrade is on, adds a nomodule redirect that sends very old browsers to the upgrade page. |
| hook | `render.after.body` | right before the closing body tag | When offline support is on, registers service-worker.js at the end of the page. |
| hook | `rebuild.after` | managed files were regenerated | Writes service-worker.js and offline.html when offline support is on, or a self-removing worker when it is off, so visitors who installed the worker earlier lose it. |
| hook | `plugin.after.disable` | disable finished | Leaves a self-removing service worker behind, so visitors' browsers drop the cached site once the plugin is off. |

Each code row matches a docblock (`Implements hook ...`, `Implements operation ...`) directly above the implementation in `src/nodejs` and `src/php`.
