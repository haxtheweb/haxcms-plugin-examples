# Import from Notion (core)

Turns a Notion export that was committed to a GitHub repository into a new site. Implements `import.platform`, which core dispatches to the importer the person picks (`dispatch: chosen`).

**What core does today.** `convertNotionToSite.js` in [haxcms-nodejs](https://github.com/haxtheweb/haxcms-nodejs) takes a GitHub repository URL, lists its files with the GitHub tree API, reads each markdown page from the raw host, pulls the Notion properties (`Lesson`, `ID`, `Type`) out of the top of the page, makes one lesson page per `Lesson` value with the pages under it, and returns every other file for download.

**What this plugin does.**

- Input `{ url }`: `https://github.com/<owner>/<repo>`, optionally `/tree/<branch>`; otherwise the repository's default branch.
- Each markdown page becomes an item under its lesson. `ID: 1.2` gives order 2; `Type` maps to `metadata.pageType` (reading, discuss, activity, connection). Lessons have `metadata.pageType: lesson`.
- Markdown is converted by `import.file` through the platform (`ctx.contracts.call`), so it depends on `import-markdown`. Scripts and inline handlers are removed (core sanitizes again).
- Images and other files are listed in `files` (`files/<path>`) for core to fetch; links to them in the pages are rewritten to that path. The importer downloads nothing itself.
- Egress is fixed to `api.github.com` and `raw.githubusercontent.com`. `github.com` itself, the host the person types, is never fetched, so `{ input: url }` would not help.

**Not ported, or changed.**

- The PHP backend's `convertNotionToSite.php` is a different, simpler importer (contents API, one level of folders, no Notion properties). This plugin follows the Node version in both runtimes.
- import-markdown is a CommonMark subset; markdown-it in core also handles tables, nested lists and more. Pages using those come over less faithfully until import-markdown grows.
- Uploading a Notion export zip directly is not supported yet. It would take `input.files` and `ctx.archive.read`, but `archive.read` returns text only, so the images in the zip could not be carried.
- Fixed while porting: when the export has no CSV, core cut the first `/` out of every path; raw URLs are now percent-encoded; a page without a title takes its file name (without the Notion hash); a page whose `ID` is not a number gets order 0 instead of `NaN`; item ids are `lesson-<slug>` and `page-<slug>` instead of random UUIDs, so both runtimes agree.
