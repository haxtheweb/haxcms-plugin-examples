# MCP (core, optional, per site)

Exposes a site to MCP clients (see https://github.com/haxtheweb/haxcms-mcp). Installed system-wide, enabled per site; HAXiam deployments block it.

- Tokens: `mcpTokenCreate`, `mcpTokenList`, `mcpTokenRevoke` (the secret is shown once; only a hash is stored)
- Discovery: `mcpDiscovery`, authenticated by the `X-HAX-MCP-Token` header, lists only operations marked `x-hax-mcp`, filtered by the token's plugin list and read-only flag, plus every plugin's prompts
- Guard: `rest.before.request` vetoes writes from read-only tokens
- Install moves the old core `mcp.readOnly` config into the plugin's settings

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `rest.before.request` | a request to a plugin or core route is about to reach its handler | Every call carrying an MCP token must have a valid token and stay inside its scope; otherwise the call is vetoed with 401 or 403. |
| operation | `mcpTokenList` | `GET /system/api/v1/plugins/<id>/tokens` (bearerAuth + userTokenHeader) | Lists the tokens that are not revoked, without their hashes. |
| operation | `mcpTokenCreate` | `POST /system/api/v1/plugins/<id>/tokens` (bearerAuth + userTokenHeader) | Issues a new MCP token, scoped to a site, a list of plugins and read-only or not, and stores only its hash; the raw token is returned once. |
| operation | `mcpTokenRevoke` | `DELETE /system/api/v1/plugins/<id>/tokens/{id}` (bearerAuth + userTokenHeader) | Marks a token revoked so later calls carrying it are refused. |
| operation | `mcpDiscovery` | `GET /system/api/v1/plugins/<id>/discovery` (public) | Tells an MCP client what its token may use: the MCP-enabled operations and prompts inside the token's plugin and read-only scope. |

Each code row matches a docblock (`Implements hook ...`, `Implements operation ...`) directly above the implementation in `src/nodejs` and `src/php`.
