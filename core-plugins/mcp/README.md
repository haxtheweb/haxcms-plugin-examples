# MCP access (core, optional)

Lets AI agents a person approves use this HAXcms through MCP (https://github.com/haxtheweb/haxcms-mcp, a separate MCP server that drives HAXcms over HTTP). Off until you enable it, and HAXiam deployments block it for now. It **requires the OAuth plugin**: MCP issues no tokens of its own.

- **On or off is this plugin.** Enabling it is what core's old `config.mcp.enabled` meant; core keeps publishing `data.mcp: { enabled, readOnly }` on `GET /system/api/v1` from this plugin's state, which haxcms-mcp already obeys.
- **Read-only by default.** The `readOnly` setting (moved from core's `config.mcp.readOnly` on the first enable) is an instance-wide switch: while it is on, tokens can only get `mcp:read`, and even a token that has `mcp:write` cannot write.
- **An OAuth resource.** Set **MCP server URL** to your haxcms-mcp address: that URL is the audience OAuth tokens are issued for. Agents connect through the normal OAuth consent screen; headless clients use an OAuth personal token for that URL.
- **What a token may call** (`check`): reads with `mcp:read`; writes with `mcp:write` and `readOnly` off; plugin operations only when marked `x-hax-mcp`; a token approved for one site stays on that site.
- **Discovery** (`mcpDiscovery`) tells the server which plugin operations (those marked `x-hax-mcp`) and prompts the calling token may use, so the server can add plugin tools without a release.
