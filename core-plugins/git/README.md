# git (version control)

Version control, extracted from core. Required.

**Today in core:** routes call `site.gitCommit(message)` after page, outline, file, settings and theme saves (`saveNode`, `createNode`, `saveManifest`, `saveSeoSettings`, `files.js`, `site.js`, ...), with an optional push to a branch (`metadata.site.git.autoPush` and `branch`), plus revision routes.

**As a plugin:** it subscribes to the page, site and file save and delete hooks; in a bulk transaction it marks the change and makes one commit in `transaction.before.end`; it defines `git.before.commit` (others may adjust the message or veto) and `git.after.commit` (for example an rsync plugin); commit messages are sanitized; it runs only `git` (`exec`); `GET .../plugins/git/history` lists recent commits. Keeping every version-control concern here is what would let something else provide history behind the same hooks.

**Core changes when extracted (not made here):** remove every `site.gitCommit` call from the routes (the hooks replace them), `GitPlus` and the git settings handling; the revision routes move here with `legacy.routes`.

Tests: `node harness/run-cases.mjs core-plugins/git` (uses real git in a temporary folder).

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `page.after.save` | the page was written to disk | Commits the site after a page is saved, or marks the change for one commit at the end of a bulk transaction. |
| hook | `page.after.delete` | the page was deleted | Commits the site after a page is deleted, or marks the change for one commit at the end of a bulk transaction. |
| hook | `manifest.after.save` | site.json was written | Commits the site after site.json is saved, or marks the change for one commit at the end of a bulk transaction. |
| hook | `file.after.save` | the file is stored | Commits the site after a file is saved, or marks the change for one commit at the end of a bulk transaction. |
| hook | `file.after.delete` | the file was deleted | Commits the site after a file is deleted, or marks the change for one commit at the end of a bulk transaction. |
| hook | `transaction.before.end` | the work is done and the transaction is about to close | Makes one commit for everything a bulk transaction changed, with a message that lists the first few changes. |
| operation | `gitHistory` | `GET /x/api/v1/plugins/<id>/history` (bearerAuth) | Lists the site's most recent commits (hash and message), newest first; limit is clamped to 1-100, default 20. |

Each code row matches a docblock (`Implements hook ...`, `Implements operation ...`) directly above the implementation in `src/nodejs` and `src/php`.
