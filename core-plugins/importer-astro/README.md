# Import from Astro (core)

Turns an [Astro](https://astro.build) site, including a [Starlight](https://starlight.astro.build) documentation site, into a new site by reading its files as data. Nothing of Astro runs: no components, no expressions, no integrations, no build. Part of https://github.com/haxtheweb/issues/issues/3364.

**As a plugin:** implements the core contract `import.platform` (dispatch `chosen`). It calls three other plugins through the platform and carries none of their code: `import-source` lists and reads the repository or zip (`import-source.tree`), `import-frontmatter` reads front matter (`import-frontmatter.data`), and `import-markdown` converts markdown (`import.file`). It has no network access of its own. `astro.config.*` is read with the same literal reader `importer-vitepress` uses: data only, never executed.

## What goes in

- **A GitHub repository URL** (`https://github.com/<owner>/<repo>`, optionally `/tree/<branch>`), or **an uploaded zip** of the same folder (`files: [{ name: site.zip, data }]`). A zip fetches nothing.
- The site is the shallowest folder holding `astro.config.mjs` (or `.js`, `.ts`, `.mts`, `.cjs`).
- It is read as a **Starlight site** when the config uses Starlight and `src/content/docs/` holds markdown; otherwise as **an Astro site**.

## A Starlight site

| In Starlight | In the new site |
|---|---|
| `src/content/docs/index.md(x)` | The home page, first. A splash page's `hero.tagline` opens it. |
| `sidebar` in `astro.config.*` | The outline, in its order. |
| A link (`'guides/example'`, `{ slug }`, `{ label, link: '/guides/example/' }`) | That page. |
| An external link (`{ label, link: 'https://…' }`) | A page holding the link. |
| A group (`{ label, items }`) | A page holding its items. |
| An autogenerated group (`{ label, autogenerate: { directory } }`, or an unlabelled `{ autogenerate }` inside a group) | The pages under that folder: `sidebar.order` first (lowest first), then by name. A subfolder is a page of its own, or its `index` page when it has one. |
| No `sidebar` | The whole docs folder, autogenerated. |
| `sidebar.hidden: true`, or a page the sidebar does not list | Kept, with `metadata.hideInMenu: true` (unlisted pages at the end). |
| Locales (`locales` with `root`, or `defaultLocale`) | The default language only; the rest counted in `stats.languageFiles`. |
| `:::note`, `:::tip`, `:::caution`, `:::danger` (with `[Custom title]`), and `<Aside type="…" title="…">` | `stop-note` (info, success, warning, stop). Other directives are unwrapped and counted. |
| `<LinkCard title href>` | A link. |
| `title` in the Starlight config | The site's title. |

## An Astro site

| In Astro | In the new site |
|---|---|
| `src/pages/**/*.md`, `.mdx`, `.html` | One page each, nested by folder (a folder's `index` page holds the pages under it; a folder without one gets a page). Siblings by title. |
| `src/pages/**/*.astro` | One page each, with the **static markup** only: the frontmatter script, `<head>`, `<style>`, `<script>`, `{expressions}` and component tags go; HTML and the text inside components stay. Titled by its first `<h1>`, else the `title` its layout component is given. |
| `src/content/<collection>/…` | Under the top-level page of the same name (`src/pages/blog/index.astro` holds `blog`), else a page per collection. Entries newest first when dated, else by title. |
| Dynamic routes (`[slug].astro`), endpoints (`rss.xml.js`), `404` and `_`-prefixed files | Not pages. Dynamic routes are counted as `route:dynamic`. |

## Both

| In the files | In the new site |
|---|---|
| `title`, else (for .astro) the first `<h1>`, else the file name | The page title. Starlight's `sidebar.label` is not used: the page keeps its own title. |
| `slug` front matter, else the file path (lower case, Astro's way) | The page's address, and its slug under its parent. |
| `draft: true` | `metadata.published: false`. |
| `pubDate`, `date`, `publishDate` or `lastUpdated` | `metadata.created` (seconds; no offset is read as UTC). |
| `tags` | `metadata.tags`. |
| MDX `import`/`export` lines | Removed; an `export` is counted. |
| `<Image>` / `<Picture>` of a file the page imports or names | An image. |
| Any other component (`Card`, `Tabs`, a site's own) | Removed, its text kept, and counted as `component:<Name>`. |
| `{expressions}` | Removed and counted as `expression`; `{/* comments */}` go uncounted. |
| Images and documents a page uses: beside it (`src/assets/…` by relative path), or from the site's root under `public/`, written with or without `base` or `site` | Listed in `files` and linked as `files/<name>`; images become `media-image`. From a repository they are listed by URL for core to fetch; from a zip they are handed over as data. |
| Links between pages (`/guides/maps/`, `../install/`, with or without `base`) | The imported page's slug. |

`stats` reports `pages`, `media`, `languageFiles`, `starlight` and, when anything was left out, `unmapped`. A sidebar that is not plain data (built from variables or functions) is counted as `config:sidebar` and the docs folder is autogenerated instead. More than 500 documents sets `truncated: true`; the rest are not imported.

## Not carried over

- **Anything a component or expression builds:** lists from `getCollection`, cards, tabs, navigation, pagination. The text written inside a component stays; the component does not.
- **Collections loaded from elsewhere** (a `loader` in `src/content.config.ts` pointing outside `src/content/`, JSON or YAML data collections) and **Markdoc** (`.mdoc`).
- **Layouts and themes**, including Starlight's own components and its i18n UI strings.
- **Markdown the shared converter does not know** (tables, nested lists, footnotes); see `core-plugins/import-markdown`.
- **Media no page refers to**, and images resolved through Vite aliases (`~/assets/…`).
- **Other forges:** only github.com repositories are read; use a zip for anything else.
