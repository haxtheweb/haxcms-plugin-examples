# Import from Plone (core)

Copies a Plone site into a new site through `plone.restapi`. Implements `import.platform`, which core dispatches to the importer the person picks (`dispatch: chosen`).

**What core does today.** `convertPloneToSite.js` in [haxcms-nodejs](https://github.com/haxtheweb/haxcms-nodejs) walks up from the given URL until `@site` answers, pages through `@search` with full objects (falling back to summaries and then fetching each item), keeps page-like content, builds the tree from each item's path and returns images and files for download.

**What this plugin does.**

- Input `{ url }`: the Plone site or any page in it (`https://plone.example.edu/history/courses/hist-101`). The URL and each parent are tried as the REST root.
- Documents, folders, news items, events, collections, links, topics and listings become pages, as do other folderish items and items with body text or a description. The tree follows the Plone path; siblings are ordered by position in parent, then title. An item whose parent folder was not imported goes to the top.
- Body HTML (`text.data`) keeps its markup with root-relative links made absolute; scripts and handlers are removed. Links become a link paragraph; items stored in Volto blocks get a placeholder paragraph, as in core.
- Images and files are listed in `files` (`files/<clean-name>`, made unique) with their download URL for core to fetch.
- Each item carries `metadata.plone` (uid, type, review state, created, modified) and `metadata.source`.
- Egress `{ input: url }`: only the host of the given URL, during the call. An item whose `@id` points at another host (a backend behind a proxy) is not fetched; its search summary is used.

**Not ported, or changed.**

- The PHP backend's `convertPloneToSite.php` is a shorter importer (documents only, no tree, no files). This plugin follows the Node version in both runtimes.
- Core's `parentId` and `maxItems` request fields and the `plone` statistics it returns; `import.platform` has no slot for them. The 5000-item cap is kept.
- A URL without `http://` or `https://` is refused instead of guessed, because core needs the full URL to open its host.
- Titles of unordered siblings are compared by code point, not `localeCompare`, so both runtimes agree.
- Volto blocks are not converted to HTML (core does not either).
- Item ids are `item-<n>` in tree order instead of random UUIDs.
