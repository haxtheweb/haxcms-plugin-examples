# Import from OpenStax (core)

Turns an OpenStax textbook into a new site. Implements `import.platform`, which core dispatches to the importer the person picks (`dispatch: chosen`).

**What core does today.** `convertOpenstaxToSite.js` in [haxcms-nodejs](https://github.com/haxtheweb/haxcms-nodejs) (and its PHP twin) resolves the book through OpenStax's public archive API (`/rex/release.json`, the CMS slug lookup, the book's `contents` JSON), fetches every page's XHTML, strips OpenStax's styling layer with a DOM parser, downloads each image into a staging folder, rewrites in-book links to the new page slugs and sets the site license.

**What this plugin does.**

- Input `{ url }`: `https://openstax.org/details/books/<slug>` or any reader page `https://openstax.org/books/<slug>/pages/<page>`. Other hosts are refused.
- Units and chapters become landing pages; sections become pages under them with nested slugs (`1-introduction-to-finance/1-1-what-is-finance`). The abstract becomes `description`.
- Page HTML keeps its structure and only meaningful attributes (`href`, `src`, `alt`, table spans, list starts); `os-*` classes, `fs-id` ids, `data-type` hooks, inline styles, scripts and handlers go. MathML is left as it is. The document title is removed from the body.
- Images are asked for their type with a `HEAD` request, listed in `files` as `files/<hash>.<ext>` for core to fetch, and shown with `media-image`. An image whose type is unknown keeps its archive URL.
- Each item carries `metadata.openstax` (book, page slug, license, `licenseCode`, publisher, accessed time from `ctx.now()`) and `metadata.source`.
- Egress `{ input: url }`: only the host of the book URL, during the call.

**Not ported, or changed.**

- The site license: core returns `site.license`; `import.platform` has no site-level field, so the code is in each item's `metadata.openstax.licenseCode` until the contract gets one.
- Core's 900-second time budget, 200 ms pause between requests and 250 MB image budget. The 500-page and 1000-image caps are kept; pages past the cap link to OpenStax. Pacing and size limits belong to core's fetch, which downloads the files.
- The `truncated` flag core returns.
- DOM parsing is replaced by regular expressions, identical in both runtimes. They assume the archive's usual shape (one `data-type="page"` wrapper around the body).
- Item ids are `item-<n>` in book order instead of random UUIDs.
