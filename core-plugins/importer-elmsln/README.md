# Import from ELMS:LN (core)

Copies an ELMS:LN course site into a new site. Implements the core contract `import.platform` (`convert`), which core dispatches to the importer the person picks (`dispatch: chosen`).

## What core does today
`convertElmslnToSite` (haxcms-nodejs `systemRoutes/v1/routes/imports/convertElmslnToSite.js`, haxcms-php `convertElmslnToSite.php`) fetches the course's `site.json` (JSON Outline Schema), then each page's HTML from its `location`, and hands the items plus a map of the files pages list to `createSite`.

## What the plugin does
- Accepts the site root or its `site.json` as `url`. Only that host is reachable, and only during the call (`egress: { input: url }`).
- Keeps each item's id, title, slug, parent, order, indent and metadata; reads the page HTML. A location that starts with the site's own name (`/<name>/pages/...`, the name from `metadata.site.name` or the last path segment) is read relative to the site.
- A page that cannot be read gets `<p>get source from <a href="...">...</a></p>` instead of failing the import, as core does.
- Files listed in `metadata.files` are returned once each in `files` for core to fetch. Scripts and inline handlers are removed (core sanitizes again).
- Returns `{ error }` when there is no `site.json` with items at the URL.

## Not ported
- Core's 300-second time budget across page fetches (pages after the budget get the source link). The platform's own call timeout applies instead.
- The PHP route's fresh UUIDs for every item and its slug cleaning; ids and slugs come over as the source has them (the Node behaviour). Core assigns new ids when it writes pages, if it needs to.
- `description` per item (PHP only).
