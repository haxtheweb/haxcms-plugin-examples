# data-store

Shows where plugin data lives and how it changes over time:

| Store | Scope | Where | Why |
|---|---|---|---|
| `votes` | site | `<site>/_config/data/data-store/votes.json` | travels with the site (export, git) |
| `notes` | siteData, `personalData` | `<HAXCMS_ROOT>/_config/siteData/<siteUuid>/data-store/notes.json` | per-user, never in the site folder; core exports and erases by `userId` |
| `feed-cache` | system | `<HAXCMS_ROOT>/_config/systemData/data-store/feed-cache.json` | one store for the deployment |
| `badge` | manifest | `site.json` at `metadata.plugins.data-store.badge` | small data that belongs inside the site file |

The upgrade step for 0.2.0 moves votes out of `site.json` (where 0.1.0 kept them) into the `votes` store through `ctx.entities`, and the list route keeps a read fallback so a site whose upgrade has not run still shows its votes. Recipe: `migrations/0002-move-votes.md`; code: `upgrades["0.2.0"]` in Node, `upgrade_0_2_0` in PHP.

Tests: `node harness/run-cases.mjs examples/data-store` (Node, PHP and parity).

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| operation | `dataStoreListVotes` | `GET /x/api/v1/plugins/<id>/votes` (bearerAuth) | Returns the vote count per page from the votes site store, falling back to the 0.1.0 location in site.json so a site whose upgrade has not run still shows its votes. |
| operation | `dataStoreVote` | `POST /x/api/v1/plugins/<id>/votes/{pageId}` (bearerAuth) | Adds one vote for a page in the votes site store, which travels with the site. |
| operation | `dataStoreCreateNote` | `POST /x/api/v1/plugins/<id>/notes` (bearerAuth) | Saves a note owned by the signed-in user in the notes siteData store, which core exports and erases by userId. |
| operation | `dataStoreGetNote` | `GET /x/api/v1/plugins/<id>/notes/{uuid}` (bearerAuth) | Returns one note, only to the user who owns it. |
| operation | `dataStoreGetBadge` | `GET /x/api/v1/plugins/<id>/badge` (bearerAuth) | Returns the site's badge from the manifest store, which lives inside site.json. |
| operation | `dataStoreSetBadge` | `PUT /x/api/v1/plugins/<id>/badge` (bearerAuth) | Sets the site's badge in the manifest store, so it is published inside site.json. |

Each code row matches a docblock (`Implements hook ...`, `Implements operation ...`) directly above the implementation in `src/nodejs` and `src/php`.
