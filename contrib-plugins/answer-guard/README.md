# Answer guard (community)

Speed bumps for question blocks on private course sites, against the "AI, answer this for me" case: a learner asks a browser agent to do the quiz, and the agent reads the page and clicks. It does not stop a determined person or agent. Anything a learner's browser can show, an agent can read and answer, iframes and shadow DOM included, because agents read pixels as well as markup. What it does is take away the free answer and make automated answering slower and visible.

## What it does

| Speed bump | How |
|---|---|
| No answer key in the page | `page.after.save` copies each guarded question's answers into the server-only `keys` store. `render.before.content` (live pages) and `entity.after.read` (pages loaded through the API) remove `data-correct`, the legacy bare `correct` and the per-choice feedback (`data-selected`, `data-unselected`) from what learners receive, and mark the block with `data-answer-guard-key`. Editors and admins get the page unchanged so they can edit it. |
| Grading on the server | `answerGuardCheck` compares the learner's choices with the stored key and answers only "correct" or "not correct", plus the feedback the author wrote for the chosen options. It never says which option is right. |
| Slower brute force | Checks of the same question closer together than `minCheckIntervalMs` (2 s) get 429. Every check is kept for the report. |
| Scripted input filtered | The `answer-guard-monitor` singleton listens in the capture phase on guarded questions. Events a script generated (`event.isTrusted` false) are counted and, with `blockUntrusted`, stopped. Keyboards, switch access and voice control produce trusted events and are never affected. Agents that drive real input pass this check, so it filters some agents, not all. |
| Signals for instructors | Before each check the monitor sends what it saw: scripted events, `navigator.webdriver`, no pointer or key input at all, and time to first input. `answerGuardSignal` keeps only flagged answers (`scripted-input`, `automation`, `no-input`, `fast-answer`). Keyboard-only answers are normal and are never flagged for a missing pointer. |
| Honor prompt | Shown once per page before the first check, in an app-styled dialog. The default text also tells learners that unusual activity is shared with their instructor. |
| Instructor report | An "Answer integrity" section in the site's Insights screen (`registries/dashboard/answer-guard-insights.yaml`) lists learners with flags. Flags are a prompt for a conversation, not proof. |

## When it applies

`protect` is `auto` by default: questions are guarded only when the site has no open license in `site.json` (`license` missing, or not CC0, CC BY-* or public domain). OER sites stay fully portable and readable, as the HAX pillars expect. `always` and `never` override it per site.

Only live pages are changed. The editor preview and static publishes (`mode` `preview` and `publish`) keep the authored HTML, because a static copy has no server to grade against. This plugin is not `staticCapable`.

## Settings

- `protect`: `auto` (default), `always`, `never`.
- `elements`: comma-separated tags with light-DOM `<input data-correct>` answers (default `multiple-choice`).
- `blockUntrusted` (true), `minAnswerMs` (1500), `minCheckIntervalMs` (2000), `honorPrompt` (empty for none).

## Data

- `keys`: answer keys by page; server only, never in the site folder or in a response.
- `attempts` and `signals`: personal data (`userKey: userId`), exported and erased by core with no plugin code.

## Not done here (see spec/GAPS.md, item 1u)

- **The question element.** `multiple-choice` grades itself from the `correct` flags it reads. With the answers removed it needs an opt-in change in https://github.com/haxtheweb/webcomponents (`QuestionElement`): when the block carries `data-answer-guard-key`, dispatch `question-check-request` with `{ choices, respond(promise) }` and use the result instead of `isCorrect()`. No attribute, usage or label changes, so existing content keeps working. Until then the monitor answers the event but the element does not send it.
- **Raw page files.** The HAXcms front end loads `pages/<slug>/index.html` directly, which bypasses both redaction hooks. Live protection needs core to serve page content through an API route (which fires `entity.after.read`) and to refuse direct reads of `pages/**` on sites where a plugin redacts content.
- **Learner calls from page singletons.** The monitor posts to its routes with the session cookie. Core has no sanctioned way yet for an injected singleton to call a plugin operation as the signed-in visitor.

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `page.after.save` | the page was written to disk | Indexes the answer keys of the guarded questions on the saved page into the server-only keys store, whatever the protect setting, so turning protection on later needs no re-save. |
| hook | `page.after.delete` | the page was deleted | Drops the deleted page's answer keys. |
| hook | `plugin.after.enable` | enable finished | When this plugin is the one enabled, indexes every existing page, so questions written before it was enabled are guarded straight away. |
| hook | `entity.after.read` | the entity or list was loaded | Removes answers from page content a learner loads through the API on a protected site. |
| hook | `render.before.content` | the page content is about to be placed in the shell | On a protected site, removes answers and choice feedback from served pages and marks each guarded question with data-answer-guard-key. |

| operation | `answerGuardCheck` | `POST /x/api/v1/plugins/<id>/check` (bearerAuth) | Grades the signed-in learner's choices for one guarded question against the stored key and says only whether they are right, with the feedback the author wrote for the choices. |
