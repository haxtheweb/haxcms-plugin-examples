# Site announcement (community, proposed)

One line of news at the top of every page of a site: a bold title, the text, an optional link, a style (brand,
neutral, success, warning, danger) and an optional last day to show it. It is drawn by `<site-announcement-bar>`
(`role: injected`), pushed right after `<body>` by `render.before.body`, so it sits above whatever the active theme
draws and works on every theme without the theme knowing about it.

- **Settings are per site** (`settingsScope: site`). Title, text and link text are cleaned to plain text (no markup or
  control characters, capped at 120 / 500 / 80 characters); the link must be http(s), mailto or a path on the site,
  or it is dropped. An unknown style falls back to brand.
- **Nothing is loaded** while title and text are both empty, or once the end date has passed (render time).
- **Static publish** works: the text is baked into attributes and the element hides itself after the end date by the
  visitor's clock, so a published copy stops showing it without a republish.
- **Dismissible.** The close button hides that announcement in that browser (localStorage, keyed by site and by the
  announcement's content); changing the text, link or end date shows it again. Nothing is tracked or sent.
- **Accessible.** A region labelled "Announcement", a 32px close button labelled "Dismiss announcement", DDD colors with
  light and dark pairs, hidden when printing.
- **Sticky headers** can offset by `--haxcms-site-announcement-height`, which the element keeps set on the root element
  to the part of the bar still on screen.

Why a plugin (https://github.com/haxtheweb/issues/issues/3358): it was first written as core site settings and a core element (webcomponents#1436, haxcms-nodejs#285,
haxcms-php#818). Most sites never need it, it touches no core data, and the render hooks already give it a place on
every theme, so it fits as an optional plugin instead of something every site carries.
