# Quick poll (community, experimental)

A poll for a page: a question with no right answer, where the point is seeing how everyone answered. This plugin ships the `quick-poll` block and counts its votes on the server, so results are real totals across learners, and gives editors a way to read and clear them.

It is **experimental**: the block shows as **Beta** in the editor's block list, and its markup or stored votes may change before 1.0.

## What learners get

The `quick-poll` block (`frontend/dist/quick-poll.js`; the DDD block frame, palette and accent support, and an xAPI `answered` statement through `user-action`):

```html
<quick-poll question="When a layout breaks, what do you do first?" show-results="after">
  <input value="Open DevTools" />
  <input value="Rewrite the CSS" />
  <input value="Ask a classmate" />
</quick-poll>
```

- pick one option and press **Vote**; results show as a row per option with the percent and count as text
- `show-results`: `after` (after voting), `closed` (after `closes` passes) or `never` (editors only, in Insights)
- `allow-change`: let a person change their vote; without it a second, different vote is refused
- if the server refuses a vote (closed, sign in needed, already voted) the reason shows and the vote is undone
- with no server (a static publish, or the plugin turned off) it still works and shows the person their own vote only

## How votes are counted

`render.after.content` gives each placed poll the address of `POST /votes?pageId=<page>`. On a vote the block sends its activity id, the option id and, to its own site only, a random key it keeps in this browser.

The server trusts none of the poll's details from the browser. It reads the poll from the page's saved content (question, options, `show-results`, `closes`, `allow-change`), finds it by the key in the activity id, and checks the option is one of its own. One vote per person: a signed-in user, or a visitor's browser (stored as a hash of the page, the poll and that key, so the same browser cannot be followed between polls). The answer carries the counts when the caller may see them, otherwise `{ counts: {}, hidden: true }`.

A `closes` time with no time zone is treated as passed once it has passed everywhere (12 hours after it passed in UTC), so results are never early anywhere.

## Settings

| Setting | Default | What it does |
|---|---|---|
| Let visitors vote without signing in | on | Off: only signed-in people can vote; visitors are told to sign in |
| Most votes per hour | 600 | A flood guard for the whole site, counted without recording who voted; 0 turns it off |

## For editors

- **Insights → Polls** lists every poll with votes: page, question, total, and each option's count and share. A poll removed from its page (or whose question was reworded) is listed as "(no longer on its page)".
- **Clear poll votes** in the Insights controls clears every poll's votes on the page Insights is showing, after a confirm. People can vote again afterwards. `POST /polls/clear` with `{ pageId, poll }` clears a single poll (`poll` from the list).
- Deleting a page deletes its polls' votes.

## Data

`ballots` (`siteData`, on the server, never in the site folder): `{ pageId, poll, voter, choice, ts }`, plus `userId` for signed-in voters, so core exports and erases a person's votes with no plugin code. No names, IP addresses or user agents. `meta` holds the flood guard's hourly count.

## Known limits

- Visitor votes are one per browser, not per person: clearing browser storage or using another browser votes again. Turn off visitor voting where that matters.
- Rewording a poll's question gives it a new key (as for its learner record), so earlier votes stay under the old one until cleared.
- `closes` is enforced on the server only once it has passed everywhere; the block stops voting at the local time.
