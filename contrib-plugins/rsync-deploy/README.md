# rsync deploy (community, Node only)

Copies the site folder to your own server with rsync over SSH, by hand (`rsyncDeployNow`) or after every git commit (`deployOnCommit`, needs the git plugin, which is only suggested).

It runs one command, `rsync`, through `ctx.exec`: an argument list with no shell, refused unless the command is in the manifest's `exec` list. The SSH key is a secret setting (`x-secret`). `ctx.exec` writes it to a private temp file for the length of the run (`files: { id: ... }`, referenced as `{tmp}/id`), and it is never logged or returned.

- `git.after.commit` is `detached: true`, so a slow copy never holds up a save.
- Turn on **Dry run** to see what would change.

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `config.before.save` | configuration is about to be written (dashboard, `hax plugin config set`, install migration) | Refuses a target that is not user@host:/path and a key that is not a private key, and warns when deploy after commit is on but the git plugin is off. |
| hook | `git.after.commit` | the commit was made (detached) | Copies the site to the target after each commit when deployOnCommit is on. |
| operation | `rsyncDeployNow` | `POST /x/api/v1/plugins/<id>/deploy` (bearerAuth) | Copies the site to the configured target with rsync right away, for an admin who does not want to wait for a commit. |
