# xAPI statements (community, Node only)

Records learners' progress (`completed`, `answered`, `experienced`) for the signed-in user and sends it to your learning record store every five minutes, in one batch.

Personal data lives in two places. Unsent statements are in a `personalData` store, which core exports and erases by itself. Sent statements are in the LRS, which only this plugin knows about, so it implements `privacy.export` (lists the sent statement ids and the LRS host) and `privacy.delete` (forgets them and warns the admin to void them in the LRS). The LRS host comes from a setting, so both `egress` and `privacy.recipients` name that setting.

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| operation | `xapiStatementsRecord` | `POST /x/api/v1/plugins/<id>/statements` (bearerAuth) | Queues a completed, answered or experienced statement for the signed-in user; the flush schedule sends the queue to the LRS. |
| contract | `privacy.export` export | core calls it (all) | Adds the ids of the user's statements that already went to the LRS, and the LRS host. |
| contract | `privacy.delete` delete | core calls it (all) | Forgets which statements went to the LRS for the user and warns the admin to void them there. |
| schedule | `flush` | `*/5 * * * *` | Sends the whole queue to the LRS in one POST every five minutes, and empties it only when the LRS accepts it. |

Each code row matches a docblock (`Implements hook ...`, `Implements operation ...`) directly above the implementation in `src/nodejs`.
