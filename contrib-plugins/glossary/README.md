# Glossary (community, Node only)

A site glossary as its own entity (`glossaryTerm`, stored in a site store that travels with the site). Entity hooks refuse duplicates (terms and aliases) for every writer: this plugin's route, an import, or another plugin saving terms.

At render, the first appearance of each term in running text becomes `<glossary-term definition="...">`, a small element this plugin ships (`role: injected`). Text inside links, headings and code is left alone. Visitors may read the term list (`optional` auth). `hax glossary list` prints it.

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `render.after.content` | the content is placed | Wraps the first appearance of each term in the page text in <glossary-term> with its definition, never inside tags, links, headings or code. |
| hook | `entity.before.create` | an entity is about to be created (any entity type the subscription lists) | Refuses a new glossary term without a definition, or whose name or aliases are already in the glossary. |
| hook | `entity.before.update` | an entity is about to be updated | Refuses a glossary term update that leaves out the term or its definition, for every writer. |
| operation | `glossaryList` | `GET /x/api/v1/plugins/<id>/terms` (anonymous or bearerAuth) | Lists the glossary terms in alphabetical order. |
| operation | `glossaryCreate` | `POST /x/api/v1/plugins/<id>/terms` (bearerAuth) | Adds a term with its definition and aliases; the entity hooks refuse duplicates and terms without a definition. |
| element | `glossary-term` | injected |  |
| CLI command | `hax glossary list` |  | List the site's glossary |
