# Comments (community)

Signed-in readers comment on pages; editors moderate. Comments are personal data kept per site on the server (`siteData` store with `personalData: true, userKey: authorId`), so core exports and erases them with no plugin code.

- Read: `commentsList` uses optional auth. Signed-out visitors get approved comments only when **Visitors can read comments** is on.
- Write: `commentsCreate` (the page must exist), `commentsModerate` (admin, editor), `commentsDelete` (author or moderator)
- `page.after.delete` deletes the page's thread.
- `render.after.content` adds approved comments to published pages (escaped). Static copies show them as of publish time (`staticFallback`).
- `user.before.erase` notes which pages show the user's approved comments (a transaction mark); `user.after.erase` lists them in `commentsRepublish` so the published copies can be refreshed.

## What it implements

| Kind | Name | Runs when | What this plugin does |
|---|---|---|---|
| hook | `page.after.delete` | the page was deleted | Removes the comments of a deleted page so none are left pointing at nothing. |
| hook | `render.after.content` | the content is placed | Appends the page's approved comments as static HTML when the snapshot setting is on, so published and static copies show them without the API. |
| hook | `user.before.erase` | core is about to erase everything kept about a user | Records, as a transaction mark, the pages that carry the user's approved comments, while the records still exist. |
| hook | `user.after.erase` | the erase finished | Adds the marked pages to the republish list, because core already removed the user's comments from the store but the published copies still name them. |
| operation | `commentsList` | `GET /x/api/v1/plugins/<id>/pages/{pageId}/comments` (anonymous or bearerAuth) | Lists the comments on a page: approved ones for everyone, plus pending ones for moderators and for their own authors. |
| operation | `commentsCreate` | `POST /x/api/v1/plugins/<id>/pages/{pageId}/comments` (bearerAuth) | Adds a comment to a page after firing comments.before.create, so other plugins (such as spam-guard) can hold it as pending, edit it or refuse it. |
| operation | `commentsModerate` | `PUT /x/api/v1/plugins/<id>/comments/{id}` (bearerAuth) | Sets a comment to approved or rejected; only admins and editors may do this. |
| operation | `commentsDelete` | `DELETE /x/api/v1/plugins/<id>/comments/{id}` (bearerAuth) | Deletes a comment when the caller wrote it or is a moderator. |
| operation | `commentsRepublish` | `GET /x/api/v1/plugins/<id>/republish` (bearerAuth) | Lists the pages that still show an erased user's comments in their published copy, so an editor knows what to republish. |

Each code row matches a docblock (`Implements hook ...`, `Implements operation ...`) directly above the implementation in `src/nodejs` and `src/php`.
